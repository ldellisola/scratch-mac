# Scratch Plan 4: Code Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scratch 0.4.0, where code looks like code:

- Fenced blocks show as tinted, rounded blocks.
  - Their fence lines shrink to thin padding, shown again only when the caret is on them.
  - A small language label sits at the top right of each block.
  - The contents are coloured by tree-sitter in Xcode's default palette.
- Pasting two or more lines that are code wraps them in a fence with the detected language. ⌘Z turns that back into plain pasted text.
- A block typed by hand gets its language detected from what's typed.
- The label is a menu for changing the language, showing plain text, or "Not Code".

The plan also tightens the bold rule, so that `x**2 + y**2` and `src/**/*.ts` stay plain (owner, 2026-10-21).

**Architecture:**
- **`Packages/ScratchCode`** is a new Swift package. It builds and tests on Linux and macOS, and wraps tree-sitter:
  - `CodeLanguage`: the 17 languages, their fence names and aliases.
  - `Highlighter`: text and a language in, `HighlightToken`s out, as UTF-16 `NSRange`s.
  - `CodeDetector`: is this paste code, and which language?
  - It has no AppKit. `ScratchCore` doesn't depend on it, so core stays Foundation-only and fast to test.
- **The app** grows from Plan 3's styler:
  - `CodeBlockStyler` asks `ScratchCode` for tokens on a background queue, and applies them as colours on the main thread when the block's text hasn't changed since the request.
  - `MarkupLayoutManager` draws the block backgrounds and labels.
  - `NoteTextView` classifies pastes and opens the label menu.

**Tech Stack:**
- Plan 3's stack, plus **tree-sitter**: the runtime and one grammar package per language, pinned to exact versions in `Package.resolved`.
- This is the one third-party dependency spec §8.1 allows. ADR 0007 records the exact packages, versions and licences.

**Spec:** [`docs/superpowers/specs/2026-10-19-scratchpad-design.md`](../specs/2026-10-19-scratchpad-design.md):
- §6.4, "Code block" row and "Code highlighting"
- §6.5, paste order
- §7, the 50 ms highlight budget and "very large pastes"
- §8.1, tree-sitter and the detection rules

Read `AGENTS.md` first, especially the Plan 3 pitfalls on the styler, null glyphs, undo groups and hosted-test clicks. Roadmap row 4: [`2026-10-19-roadmap.md`](2026-10-19-roadmap.md).

**Branch:** `plan-4-code`, from `main` at 0.3.0. One PR at the end, which publishes 0.4.0 (DMG and zip).

## Global Constraints

Everything in Plans 1–3 still applies (AGENTS.md section 5). In addition:

**Characters and paste**
- **Characters are never changed by highlighting or rendering.** The only edits are the explicit ones, each one undo step:
  - a code paste's fence wrap
  - the label menu's language change
  - "Not Code"
- **A pasted code block is two undo steps.**
  1. The plain paste.
  2. The fence wrap, applied on the **next main run loop turn**, so it can't share an undo group with the paste (AGENTS.md, "Undo steps cannot be tested in a hosted test across two edits").

  ⌘Z once leaves exactly the plain pasted text. ⌘Z again removes it.
- **Pasted code keeps every character**: no re-indenting, no trimming, and line breaks as pasted. The fence lines are added around it: before it when the paste doesn't start a line, and after it when it doesn't end one.

**Detection** (spec §6.4, §8.1)
- Only pastes of **two or more lines** are candidates.
- Never a paste inside an existing code block or inline code. Never a paste that already contains a fence line.
- **Prose stays prose.** When unsure, it isn't code.
- Detection is offline and deterministic, and takes under 20 ms for 500 lines (Release).

**Blocks** [calls]
- The background is the existing `CodeBackground` asset, as a rounded rect with a 6 pt radius.
- Block lines have a 10 pt head indent and a 10 pt tail indent.
- Fence lines are drawn as 6 pt high padding: null glyphs, plus a paragraph style with a maximum line height of 6 pt. While the caret or selection touches a fence line, it's shown in full in `tertiaryLabelColor`.
- The label is `secondaryLabelColor`, 2 pt smaller than the note font, at the block's top right.
  - A detected language is shown in italics, which means "auto".
  - A block that is too long to colour shows its name only.
- **Too long to colour:** over 5,000 lines or 300,000 UTF-16 units. The block stays tinted but isn't coloured (spec §7).

**Performance**
- No budget may `FAIL`.
- A new metric, `paste_code_ms` (budget 50, spec §7), runs from the paste until the colours are on screen. It's added to `perf/budgets.json`, with a baseline taken from the slowest of three CI runs (ADR 0003).
- Highlighting never runs on the main thread. The main thread only applies colours: for a shown note, visible blocks first and the rest in idle chunks, like Plan 3's styling.

**Release**
- `VERSION` becomes `0.4.0` in Task 1.

```swift
public enum CodeLanguage: String, CaseIterable, Sendable {
    case swift, python, javascript, typescript, json, bash, sql, yaml, html, css, csharp, go, rust, c, cpp, java, powershell
    public static func fromFence(_ name: String) -> CodeLanguage?   // aliases, case-insensitive
    public var fenceName: String { get }                            // canonical
    public var label: String { get }                                // "C#", "C++", "Shell", …
}
public enum HighlightKind: String, Sendable { case keyword, string, comment, number, type, function, attribute, preprocessor }
public struct HighlightToken: Equatable, Sendable { public let range: NSRange; public let kind: HighlightKind }
public final class Highlighter: Sendable {
    public static let shared: Highlighter
    public static let maximumLines = 5_000, maximumLength = 300_000
    /// nil when the text is over the cap. Ranges are UTF-16, relative to `text`, sorted, non-overlapping.
    public func tokens(in text: String, language: CodeLanguage) -> [HighlightToken]?
    /// Share of the syntax tree that is ERROR or MISSING nodes, 0…1 (for CodeDetector).
    public func errorRate(of text: String, language: CodeLanguage) -> Double
}
enum CaptureMapping { static func kind(forCapture name: String, language: CodeLanguage) -> HighlightKind? }
```

**Behaviour:**
- **Wrapper.** Use `tree-sitter/swift-tree-sitter` (formerly ChimeHQ/SwiftTreeSitter) for parsing and queries, including the `#eq?` / `#match?` predicates, if its products build and pass these tests on **both** the Linux job and the macOS job. If they don't, write a thin wrapper over the tree-sitter C API in `Highlighter.swift`. It must evaluate `#eq?`, `#not-eq?`, `#match?` and `#not-match?`, and ignore other directives.
- **Grammars.** Each comes from its own SPM package (Swift: `alex-pinkus/tree-sitter-swift`, whose generated parser is on a tag or branch that includes `src/parser.c`; Python: `tree-sitter/tree-sitter-python`), pinned with `exact:`. Each queries file comes from the grammar package's resources. Where a package doesn't ship it, copy it into `Sources/ScratchCode/Queries/<language>/` with its licence.
- **Threads.** Parsers are created per call, or per thread from a pool, because tree-sitter parsers aren't thread-safe. A language's compiled query is created once, behind a lock.
- **Overlaps.** Overlapping captures resolve to the innermost (narrowest) one. Same width: the later capture in the query wins.
- **ADR 0007** records:
  - the wrapper choice and why
  - every package with its URL, exact version and licence
  - how to add a language: package, queries, the `CodeLanguage` case, corpus samples, a highlighter test
  - the app size before and after

### Task 4: Code detection

This covers Review Focus 1.

**Files:**
- Create: `Packages/ScratchCode/Sources/ScratchCode/CodeDetector.swift`, `DetectionFeatures.swift`, `Tests/ScratchCodeTests/CodeDetectorTests.swift`, and `Corpus/<language>/*.txt` and `Corpus/prose/*.txt` (+)

**Interfaces:**

```swift
public struct CodeDetection: Equatable, Sendable { public let language: CodeLanguage?; public let confidence: Double } // language nil = code of an unknown language
public enum CodeDetector {
    /// nil = not code (stays prose). Only call it for text of two or more lines; a single line returns nil.
    public static func detect(_ text: String) -> CodeDetection?
}
```

**The algorithm** [builder, within spec §8.1]. It's deterministic: no randomness, and no dictionary with an unstable order.

1. **Cheap features over the lines**, in `DetectionFeatures`:
   - the share of lines that end in `;`, `{`, `}`, `)`, `:` or `,`
   - the indentation share
   - the symbol density (`{}[]()<>=;:$#@*&|`)
   - the share of lines that start with a keyword from any language
   - the share of lines that look like sentences: a capital first letter, mostly letters, ending in `.`, `?` or `!`
   - shebangs, `<?xml`, `<!DOCTYPE`, `<html`
   - JSON shape: the text parses with `JSONSerialization` and starts with `{` or `[`
2. **A code score** from those features. Below a threshold, the result is nil: prose.
3. **Strong signals** decide a candidate language directly:
   - a shebang (`bash`, `zsh`, `sh` → bash, `python` → python, `node` → javascript)
   - JSON shape
   - `<?php` → nil (unknown)
   - `SELECT … FROM`
   - `func`, `let` and `var` with `:` types → swift
   - `def … :` or `import` → python
   - `package main` → go
   - `fn` with `let mut` → rust
   - `#include` → c or cpp (cpp when it has `::`, `std::` or `class`)
   - `using System` or `namespace` with `{` → csharp
   - `public class`, or `System.out` → java
   - `$` variables with `-Verb` cmdlets (`Get-`, `Set-`) → powershell
   - `<tag>` structure → html
   - selectors followed by `{ prop: value; }` → css
   - `key: value` lines with `- ` lists and no braces → yaml
   - `interface`, `: string` or `<T>` with `const` or `let` → typescript, otherwise javascript
4. **Ties.** When no strong signal, or several, decides, compute `Highlighter.errorRate` for the top candidates (at most 4) and pick the lowest error rate.
   - If the best rate is over 0.15, return `language: nil` (an unknown language) when the code score is high, and nil (prose) otherwise.

**Time:** under 20 ms for 500 lines in Release, and under 100 ms in the Debug test run.

**Behaviour:**

**Interfaces:**

```swift
enum PasteClassifier {
    /// The fence wrap for a paste that was just inserted at `range`, or nil to leave it plain.
    static func wrap(pasted: String, at range: NSRange, in text: NSString, isInCode: Bool) -> TextEdit?
}
```

**Behaviour** (spec §6.5 paste order; file references and images are Plan 5):
1. `paste(_:)` inserts the pasteboard's plain text exactly as Plan 1 does.
2. On the next main run loop turn (`DispatchQueue.main.async`), it asks `PasteClassifier.wrap`. Wrap returns nil when:
   - the paste is fewer than two lines
   - `isInCode` is true
   - the pasted text contains a fence line
   - `CodeDetector.detect` returns nil

   Otherwise it returns an edit that inserts `` "```" + fenceName + "\n" `` before the pasted range (prefixed with `"\n"` when the paste didn't start a line) and `` "\n```" `` after it (followed by `"\n"` when the paste didn't end a line). An unknown language gives a fence with no name.
3. `apply(_:)` applies the wrap: one undo step, separate from the paste's. If the text changed between the paste and the wrap, the classifier isn't run.
4. The `paste-code` signpost interval runs from `paste(_:)` until the block's colours are applied (`RunLoopIdle`).
